# 초록정원 연구기지 태블릿 탐구 경험 설계

작성일: 2026-10-16. 개정: 학생 UX·교육과정 재검토 반영 2차안. 대상: 초등 3학년 과학 「식물의 생활」. 상태: 구현 전 개선 설계.

관련 문서: [전체 화면·성취기준 재검토](reviews/UX-CURRICULUM-REVIEW-20261016.md), [실행 계획](IMPLEMENTATION-PLAN-20261016.md). 학생용 제목·문구·기본/확장 경계는 재검토 문서를 함께 적용한다.

태블릿에서 학생이 대상을 직접 조작하고, 조작에 따른 현상을 관찰하고, 자신의 증거로 설명하는 경험을 만든다. 대표 경험은 **잎의 단서 발견, 겨울에서 다음 해 봄으로 시간 이동, 가방 부품 변경 전후 비교**다. 기존 5개 미션·10개 활동·연구기지 복구 이야기를 유지한다.

이 문서는 다음 개편의 기능·화면·완료 조건 기준이다. 현재 실행 버전은 0.3이며, 본문의 신규 동작과 판정은 아직 구현되지 않았다. 기존 PRD/TRD의 2D 활동, 정적 앱, 개인정보 미수집, 관리자 미리보기와 접근성 원칙을 이어받는다.

## 1. 설계 원칙과 범위

### 학생이 경험할 공통 흐름

**짧게 예상하기 → 손으로 조작하기 → 현상 보기 → 내가 본 증거 남기기 → 조건 하나를 바꿔 비교하기.**

모든 활동에 다섯 단계를 반복해서 요구하지 않는다. 관찰에서는 발견, 계절에서는 시간과 비교, 실험에서는 조작과 현상, 발명에서는 수정과 비교를 집중시킨다. 분류·서식지·보고는 그 증거를 활용하는 짧은 활동으로 둔다.

- 조작은 학습 대상에 일어난다. 잎의 가장자리를 짚고, 잎자루를 물속에 놓고, 가방 입구를 덮는다.
- 애니메이션은 원인을 설명한다. 물방울 경로·남아 있는 뿌리·배치 변화가 보이며 장식용 반복 동작은 줄인다.
- 정답 설명은 현상을 관찰한 다음 제공한다. 예상의 정오, 속도, 시도 횟수는 감점하지 않는다.
- 실험 결과 자체와 학생의 해석을 분리한다. 단서를 보는 것만으로 정확한 해석까지 자동 완료하지 않는다.
- 비교에 필요한 관찰 결과는 나란히 유지한다. 조건을 바꾸었다고 이전 결과를 지우지 않는다.
- 잘못된 선택은 다시 조사할 단서가 된다. 정확한 터치 위치, 긴 누르기 시간, 조작 순서 암기는 학습 성취로 평가하지 않는다.
- 모든 드래그·핀치에는 선택 후 누르기·확대 버튼·키보드 대안을 제공한다. 같은 증거와 완료 조건을 적용한다.
- 기본 조작은 ‘고르고 누르기’로 통일하고 제스처는 지름길로 제공한다. 한 장에서 새 필수 조작을 여러 개 가르치지 않는다.
- 기본 완료와 더 해보기를 구분한다. 두 번째 분류 기준·추가 계절 사진·두 번째 가방 비교는 선택 활동이며 다음 미션을 막지 않는다.
- [4과03-01~03]에 맞춰 잎의 외형 관찰·분류, 식물과 환경의 관계 설명, 생활용품 설계와 협력적 소통을 중심으로 둔다. 계절은 연결 탐구, 내부 구조는 보조 관찰이며 별도 단원의 성취를 모두 달성했다고 표시하지 않는다.

### 유지와 변경

| 유지 | 변경 |
|---|---|
| 5개 미션과 10개 활동, 기존 캐릭터와 식물 | 관찰·실험을 물체 직접 조작으로 개편 |
| 2D 활동, 정적 배포, 현재 JS 모듈 구조 | 태블릿에서 대상·도구·결과가 함께 보이는 화면 |
| 6×4 정원, 세 가지 대표 환경 | 칸 수 충족 이후 증거를 이용한 정원 점검 |
| 보통 천/연잎 코팅 × 열린 입구/덮개 조합 | 한 부품씩 바꾸는 공정한 비교와 물의 경로 |
| 기기 저장, 관리자 전체 미리보기 | 조작 증거·비교 쌍 저장과 기존 저장 이관 |

이번 설계에는 카메라·센서 권한, 실제 기기 기울이기 필수 조작, 온라인 협동, 서버, 자유 서술 AI 채점, 3D 물리 엔진을 넣지 않는다. 화면의 기울이기 손잡이는 선택적 탐색 도구로만 사용한다.

## 2. 화면과 터치 설계

### 가로 태블릿 기본 구성

1280×800과 1024×768을 우선한다. 브라우저의 실제 사용 가능 높이를 기준으로 배치하며 1280×720에서도 핵심 조작을 유지한다.

```text
┌─────────────────────────────────────────────────────────┐
│ 홈·이전    초록정원 / 현재 미션                  소리·설정 │
├─────────────────────────────────────────────────────────┤
│ 활동 제목     지금 할 일 한 문장                 증거 2/3 │
├────────────────────────────────────┬────────────────────┤
│                                    │ 지금 쓰는 도구      │
│         큰 관찰·실험 대상           │ 비교할 대상        │
│       변화와 원인이 보이는 영역     │                    │
│                                    │ 최근 증거 1장      │
├────────────────────────────────────┴────────────────────┤
│ 현재 현상 한 문장        핵심 조작           증거 기록    │
├─────────────────────────────────────────────────────────┤
│ 연구 노트 3장                         다음 탐구          │
└─────────────────────────────────────────────────────────┘
```

1280×800 설계 예산: 공통 메뉴 64px, 제목·지시 80px, 활동 영역 496px, 활동 도구 72px, 탐색 64px, 나머지 안전 여백 24px. 1024×768에서는 활동 영역을 464px로 줄인다. 이 값은 배치 검토용이며 고정 높이를 누적해 화면을 넘기지 않는다. 실제 구현은 grid의 `minmax(0, 1fr)`와 콘텐츠 크기를 함께 사용한다.

- 활동 영역은 약 70:30으로 대상과 도구를 나눈다. 비교 시험 때는 대상 영역을 두 장면으로 분할한다.
- 제목·캐릭터 의뢰를 하나의 짧은 줄 또는 두 줄로 통합한다. 큰 캐릭터는 도입과 보상에 사용한다.
- 기록 수첩 전체를 항상 펼치지 않는다. 최근 증거 1장만 표시하고 전체 노트는 별도 패널에서 연다.
- ‘비 뿌리기’, ‘물속에 놓기’, ‘시간 이동’은 첫 화면에 노출한다. 현재 단계의 핵심 실행 하나만 강조한다. 완료 전 ‘다음’ 옆에는 실제로 남은 행동을 안내한다.
- 학생 화면에서 MISSION, SPECIMEN, OBSERVATION LAB 같은 영어 장식 문구와 중복 의뢰 제목을 제거한다. 활동 제목은 ‘잎을 살펴봐요’, ‘식물이 사는 곳’처럼 행동을 드러낸다.
- 헤더의 이전 이동은 목적지에 맞는 글자를 함께 표시한다. 지도 복귀와 앞 활동 이동을 모두 같은 뒤로 아이콘으로 표현하지 않는다.
- 도구와 탐색 영역은 레이아웃 안에 자리를 갖는다. 위에 덮이는 고정 하단바를 사용하지 않는다.
- 큰 글자·세로 방향·브라우저 확대에서는 자연스러운 세로 스크롤을 허용한다. 화면에 맞추려고 글자를 작게 줄이지 않는다.
- 본문·주요 버튼 18~22px, 설명 16~18px, 목표 터치 영역 48px 이상. 가로가 부족하면 도구를 묶고 줄을 바꾼다.
- 선택은 테두리·체크·문구로 함께 표현한다. 정답/재관찰 상태를 색만으로 구분하지 않는다.

### 조작과 피드백

| 입력 | 시각적 반응 | 대안 |
|---|---|---|
| 돋보기 끌기·핀치 | 손 위치를 따라 확대 영역 이동, 단서 위치 표시 | 확대 버튼 + 부위 선택 |
| 잎자루 물속으로 끌기 | 수면 아래로 들어가는 모습과 상태 변경 | 표본 선택 → 물 누르기 |
| 잎자루 누르기 | 누른 동안 변형과 공기 방울 발생 | ‘누르기’ 버튼·Space |
| 시간 막대 쓸기 | 같은 식물의 계절 변화, 현재 연도·계절 유지 | 이전/다음 시점 버튼 |
| 지형 쓸어 칠하기 | 지나간 칸만 지형 변경, 한 획 되돌리기 | 도구 선택 → 칸 누르기 |
| 가방 부품 변경 | 변경한 부분 강조, 이전 시험과 다름 표시 | 부품 카드 선택 |

모션 감소 설정에서는 이동·기포의 시작/중간/결과를 정지 장면으로 제공한다. 의미 있는 결과는 소리 없이도 확인 가능하다. 손가락에 가려지는 단서는 터치 위치 위쪽의 확대창에서 보여 준다. 입력 취소·화면 이탈 시 잡고 있던 상태와 애니메이션을 정리한다.

## 3. 열 개 활동의 상세 설계

### 1장 잎 속 단서 찾기

**대표 장면:** 잎 가장자리로 돋보기를 옮기자 톱니가 보이고, 학생이 짚은 부위가 증거 카드로 남는다.

1. 벚나무 잎을 크게 제시한다. 첫 안내는 “잎의 가장자리를 살펴볼까요?”로 제한한다.
2. 가장자리 또는 전체 잎을 누르면 크게 볼 수 있다. 돋보기 이동과 핀치는 선택 도구이며 1.2배 같은 배율을 완료 조건으로 삼지 않는다.
3. 부위를 짚으면 그 부분의 확대 그림과 특징 보기가 열린다. 특징을 고를 때 해당 관찰 그림이 함께 기록된다. 별도의 캡처→저장→확인 버튼을 반복하지 않는다.
4. ‘큰 톱니가 보임/큰 톱니가 보이지 않음’, ‘끝이 뾰족한 넓은 잎/가늘고 긴 잎/부채 모양 잎’처럼 그림으로 구분할 수 있는 보기를 쓴다. 강아지풀의 미세한 거친 가장자리를 절대적으로 없다고 단정하지 않고 교과용 관찰 그림의 범위를 밝힌다.
5. 은행나무·강아지풀도 관찰하고 필요할 때 두 잎을 겹치거나 나란히 비교한다.

모양은 전체 윤곽, 가장자리는 넓게 잡은 관찰 영역을 인정한다. ‘없음’도 관찰 증거로 인정한다. 고정된 한 픽셀 찾기가 되지 않도록 판정 영역을 넉넉하게 두고, 대체 조작에서는 부위 선택으로 동일한 증거를 만든다.

**완료:** 3종 각각 모양·가장자리 증거와 특징 연결을 확인한다. 틀리면 관련 부위 비교를 제안하고 학생이 해석을 수정한다. 다음 장에는 학생이 만든 증거 카드 6장이 전달된다.

### 2장 기준을 바꾸는 분류 연구실

**대표 장면:** 같은 잎이 기준에 따라 다른 무리에 속하는 것을 두 분류판에서 비교한다.

- 학생이 ‘큰 톱니가 보이나요?’ 또는 ‘가늘고 길쭉한가요?’ 중 관찰한 특징에 맞는 기준을 고른다. 첫 화면에는 분류판 하나만 보인다.
- 식물 카드를 고른 뒤 놓을 모둠을 누른다. 모둠에는 선택한 기준을 반복하지 않는 짧은 라벨과 그림을 붙인다. 관련 관찰 카드는 식물 옆에서 바로 펼친다.
- 기본 분류를 마치면 ‘다른 기준으로 해보기’를 선택할 수 있다. 이때 이전 판을 보존하고 두 판에서 같은 식물을 비교한다. 완성 전 정답 이동을 자동 실행하지 않는다.
- 잘못 놓으면 ‘틀림’ 대신 해당 관찰 카드와 분류 질문을 함께 보여 준다.

**기본 완료:** 학생이 고른 기준 하나에서 3종의 분류가 맞고, 한 식물의 특징을 기준과 연결한다. **더 해보기:** 다른 기준의 분류와 소속 변화 비교. 두 번째 판은 기본 완료에 요구하지 않는다.

### 3장 겨울을 지나 다음 해 봄으로

**대표 장면:** 땅속 창을 연 채 시간을 움직이면 겨울에 남아 있던 뿌리와 다음 봄의 생장을 연결해서 볼 수 있다.

- 시간 순서는 ‘올해 여름 → 가을 → 겨울 → 다음 해 봄’이다. 봄을 겨울 이전에 표시해 다음 해라는 설명과 충돌하지 않게 한다.
- 시간 막대를 쓸면 같은 개체의 변화가 이어진다. 역방향 탐색에는 ‘지난 모습 다시 보기’를 표시한다.
- 땅속 관찰창은 ‘땅속 보기’ 버튼으로 연다. 손잡이 이동은 선택 조작이며 시간 이동 후에도 관찰창 상태를 유지한다.
- 기본은 선택한 식물 하나를 본다. 벚나무와 씀바귀 나란히 보기는 더 해보기로 제공한다. 살아 있는 부분의 해석은 앱에서 제공하는 연속 관찰 자료와 연결하며 단지 뿌리 그림이 보인다는 것만으로 생존을 입증했다고 하지 않는다.
- 학생이 선택한 시점과 관찰창 상태를 ‘사진 남기기’로 저장한다. 사진은 원본 파일 업로드가 아닌 앱 그림의 상태 기록이다.

**기본 완료:** 선택한 식물의 겨울·다음 봄 2장을 확보한다. **더 해보기:** 두 번째 식물·여름·가을·땅속 비교. 겨울과 봄의 차이는 4장에서 다룬다. 계절 애니메이션은 관찰 모형이며 실제 생장 속도를 뜻하지 않는다. 이 활동은 ‘식물의 생활’에 연결한 탐구이며 한해살이/여러해살이 유형 전체의 성취 평가가 아니다.

### 4장 내가 찍은 사진으로 설명하기

- 3장에서 선택한 식물의 겨울·다음 봄 사진 두 장을 자동으로 나란히 제시한다. 학생이 서랍에서 사진을 다시 찾고 옮길 필요는 없다.
- 다음 봄 사진에서 새로 보이는 잎·싹·꽃 중 한 곳을 고르면 겨울의 같은 위치가 함께 강조된다. 모든 부위 표시와 문장 완성을 중복 과제로 요구하지 않는다.
- ‘겨울을 지낸 같은 식물에서 다시 자랐어요’라는 설명에 두 사진을 연결한다. 보기만 했다고 설명이 자동 완료되지 않는다.
- 두 번째 식물을 비교할 때는 해당 식물의 사진으로 교체한다. 기록이 없으면 관찰로 이어 주며 관련 없는 카드를 여러 장 제시해 찾기 과제로 만들지 않는다.

**완료:** 같은 식물의 겨울·다음 봄 사진에서 차이 하나를 찾고 관찰 내용과 설명을 연결한다. 겨울 사진의 뿌리는 모형의 표현임을 작은 설명으로 유지한다.

### 5장 손으로 확인하는 잎자루 실험

**대표 장면:** 물속의 잎자루를 누를 때 표본이 눌리고 단면에서 공기 방울이 올라온다.

1. 잎자루가 어느 부위인지 전체 식물에서 가리킨다. 예상은 선택 활동으로 두고, 바로 살펴보기도 허용한다.
2. ‘자른 면 보기’를 누르면 단면을 연다. 정확한 절단선을 따라 끌기는 요구하지 않는다. 실제 칼 사용을 안내하지 않는다.
3. 단면의 공간을 살핀 뒤 표본을 물속에 놓는다.
4. 표본을 누르면 변형과 기포가 함께 나타나고, 놓으면 변형이 돌아온다. 누르기 강도나 시간으로 실제 공기량을 계산하지 않는다.
5. ‘공기 방울이 나왔어요/물만 보였어요/모르겠어요’로 본 현상을 고른다. 공기 공간과 기포 장면을 연결한다.
6. 더 알아보고 싶을 때 알로에 잎을 옆에 놓고 물을 담은 두꺼운 잎과 비교한다. ‘조직’ 같은 내부 구조 용어의 암기를 요구하지 않는다.

다시 누르기는 새 실험을 반복한 관찰 모형으로 처리한다. 무한 공기 발생처럼 보이는 상시 기포는 사용하지 않는다. 각 시도 후 ‘새 표본으로 다시 보기’를 제공한다.

**기본 완료:** 잎자루의 큰 부위 관찰, 물속 누르기 또는 동일한 대체 조작, 공기 방울 관찰과 생김새 연결. **더 해보기:** 상세 단면·알로에 비교. 내부 구조 지식을 기본 완료로 요구하지 않는다. 완료 버튼은 단순 단계 카운터만으로 활성화하지 않는다.

### 6장 증거로 고르는 식물의 자리

- 먼저 환경 그림에서 물·땅의 상태를 살핀 뒤 식물을 놓는다. 다음으로 해당 식물의 관찰 카드 2~3개 중 까닭을 고른다. 환경과 이유를 한꺼번에 지시하지 않는다.
- 자신의 기록이 있으면 사용하고, 선택 탐구에서 보지 않은 알로에·뿌리 자료는 이 화면에서 관찰할 수 있는 제공 카드로 보여 준다. ‘내가 본 기록’과 ‘새로 볼 그림’을 구분하고 없던 개인 기록을 만들지 않는다.
- 부레옥잠에는 잎자루 공기 공간과 물 위 모습, 알로에에는 수분 조직과 건조 환경, 벚나무에는 뿌리와 땅의 관계를 보여 준다.
- ‘어디에 살까요?’와 ‘어떤 특징이 도움이 될까요?’를 하나의 연결 장면으로 묶는다. 드롭다운 이유 선택은 증거 카드 선택으로 대체한다.
- 배치 즉시 죽거나 다른 식물로 변하는 표현은 하지 않는다. 대표 환경과 특징을 연결하는 모형으로 제한한다.

**완료:** 세 식물의 환경과 근거 카드가 연결된다. 정답 표시 전에 학생의 선택을 유지하며 관련 기록을 다시 볼 수 있다.

### 7장 내 정원의 환경 만들기

- 기본은 세 구역이 각각 3칸 이상 준비된 6×4 정원을 수정한다. ‘빈 정원부터 만들기’는 선택이다. 도구와 격자 전체가 동시에 보인다.
- 처음부터 ‘3칸 채우기’를 크게 제시하지 않고 ‘세 식물이 머물 자리를 만들어요’를 중심 목표로 둔다. 각 구역 3칸 조건은 정원 설계 규칙으로 안내한다.
- 현재 브러시, 지우개, 한 획 되돌리기만 기본 도구로 둔다. 식물 자리 미리보기는 원하는 때 켠다.
- 세 구역을 어떻게 배치할지는 학생이 정한다. 특정 모양의 정원을 정답으로 강제하지 않는다.

**완료:** 세 구역 각각 3칸 이상. 3칸은 게임 공간 규칙이며 실제 식물의 생육 면적 기준이 아니다. 지형 배치는 8장·지도·엔딩에서 그대로 사용한다.

### 8장 내 정원을 점검하고 고치기

**대표 장면:** 내가 만든 정원을 점검하면 식물 자리와 관찰 증거가 연결되고, 자리를 옮긴 결과를 바로 확인한다.

- 6장의 식물·증거 카드로 정원에 심는다. 식물 선택 → 칸 누르기를 기본으로 제공한다.
- ‘정원 살펴보기’를 누르면 식물별로 물 위의 모습, 잎 안쪽, 뿌리와 땅의 관계를 짧게 보여 준다. 성장률·생존율·물리적 수위 계산은 하지 않는다.
- 어울리지 않는 자리에는 질문 표식을 붙인다. 학생이 해당 식물의 기록을 열고 자리 또는 지형을 바꾼다.
- 모든 자리를 맞게 골랐다면 불필요한 실패를 강요하지 않는다. 식물 하나의 증거를 열어 이유를 연결하면 된다.

**완료:** 서로 겹치지 않는 세 식물, 각 대표 환경과 근거 연결, 최신 정원에 대한 점검 1회. 점검 후 지형·배치를 바꾸면 현재 정원 점검만 다시 요구한다.

### 9장 연잎의 특징으로 가방 만들기

- ‘수첩이 젖고 가방에 흙이 묻었어요’라는 문제를 그림으로 제시한다.
- 연잎 표면 모형에 물방울을 떨어뜨린다. 선택적 기울이기 손잡이로 물방울이 굴러가는 모습을 본다. 손잡이는 화면 내 도구이며 기기 센서를 요구하지 않는다.
- 가방 겉면과 입구를 별도 선택한다. 코팅은 겉면의 물방울·먼지 제거, 덮개는 입구 보호에 대응한다.
- 학생이 원하면 결과를 예상한다. ‘바로 시험하기’도 허용하며 예상·정답 설계를 진입 조건으로 삼지 않는다.

**완료:** 연잎 관찰과 특징 연결, 첫 설계 저장. 어떤 조합으로든 10장 시험을 시작할 수 있다. ‘연잎 코팅’은 학생 화면에서 ‘연잎을 닮은 겉면’으로 표시하며 기술 용어만으로 선택을 요구하지 않는다.

### 10장 같은 비에서 한 부품씩 바꾸기

**대표 장면:** 두 가방에 같은 비가 내리는데 겉면과 입구에서 물의 경로가 다르다. 바꾼 부품과 달라진 결과가 한 화면에 보인다.

1. 첫 시험은 현재 가방을 크게 보여 준다. 물방울이 표면을 따라 움직이는 경로와 입구로 들어가는 경로를 구분한다.
2. 시험 후 수첩과 겉면을 직접 확인한다. ‘안이 젖음/젖지 않음’, ‘먼지가 남음/떨어짐’을 관찰 카드로 고른다.
3. 바로 앞 시험은 앱이 보존한다. 학생은 ‘하나만 바꿔 볼까?’에서 겉면 또는 덮개 하나를 고른다. 비교 쌍 고정 같은 관리 조작은 앱이 맡는다.
4. 비교 중 다른 부품과 비·먼지 조건은 동일하게 유지한다. 두 가방을 나란히 놓고 같은 재생 시점으로 시험한다.
5. 바뀐 부품과 바뀐 결과를 학생이 연결한다. 이전 결과와 예상이 달라도 감점하지 않는다.
6. 최신 설계에서 두 목표를 모두 해결하면 완료한다. 자유 조합은 가능하지만 두 부품을 동시에 바꾼 비교는 한 부품의 효과를 확인한 증거로 인정하지 않는다.

| 겉면 | 입구 | 모형의 관찰 결과 |
|---|---|---|
| 보통 천 | 열림 | 수첩 젖음, 먼지 남음 |
| 연잎 코팅 | 열림 | 수첩 젖음, 먼지 떨어짐 |
| 보통 천 | 덮개 | 수첩 젖지 않음, 먼지 남음 |
| 연잎 코팅 | 덮개 | 수첩 젖지 않음, 먼지 떨어짐 |

**기본 완료:** 식물 특징을 활용한 최신 설계, 그 설계의 시험, 한 부품만 바꾼 비교 1쌍과 결과 설명. 두 기능 성공은 이 이야기의 권장 목표이며 성취기준 달성을 성공 조합 하나로 환원하지 않는다. **더 해보기:** 겉면·덮개 각각의 효과를 비교하는 두 쌍 또는 네 조합 탐색. 처음부터 성공한 학생에게 일부러 실패하거나 세 가지 설계를 모두 만드는 것을 요구하지 않는다.

대표 확장 경로: 보통 천+열림 → 연잎 코팅+열림 → 연잎 코팅+덮개. 두 번째 시험의 ‘겉은 깨끗하지만 안은 젖음’이 핵심 발견이다. 기존처럼 2.1초 기다린 뒤 결과만 교체하지 않고, 진행 중 경로와 결과가 연결된다. 일시정지·다시 보기를 제공하며 기다린 시간은 평가하지 않는다. 이 경로를 따라 한 것만으로 학생의 이해를 자동 인정하지 않는다.

## 4. 최종 보고와 보상

최종 보고에는 학생이 선택한 잎 단서, 겨울·봄 사진, 기포 관찰, 실제 정원, 가방 비교 쌍이 자동으로 묶인다. 다섯 카드를 각각 제출하는 반복 조작을 없애고 소개할 발견 하나를 고른다.

- 마지막 새 상황 적용은 새 잎 분류 또는 새 식물과 환경 연결 중 하나로 구성한다. 나머지는 더 해보기에 둔다.
- 정원·가방의 최신 유효성은 앱이 검사하고, 바뀐 부분만 재확인을 안내한다. 이미 한 판정을 다시 버튼으로 확인하게 하지 않는다.
- ‘내 가방 소개’에서 학생이 식물의 어떤 특징을 어느 부분에 썼는지 말한다. 옆 친구가 질문·의견을 말하면 설계를 바꾸거나 유지한 까닭을 설명한다. 말하기 틀은 제공하지만 정답 문장을 자동 완성하지 않는다.
- 협력 활동은 같은 기기 앞 대화로 수행한다. 이름·음성·온라인 전송을 요구하지 않는다. 혼자 할 때는 ‘나중에 이야기하기’를 허용하고 개인 탐구 완료와 소통 확인을 구분한다. 대화 버튼을 눌렀다는 이유만으로 협력적 소통 성취를 인증하지 않는다.

기존 빛씨앗 5개·시설 복구·꽃길 선택을 유지한다. 반복 탐구로 보상이 중복 지급되지 않는다. 보상 직전에 ‘내가 발견한 장면’이 시설의 연구 기록으로 들어가며, 엔딩에는 학생의 실제 정원과 가방이 나타난다.

## 5. 증거와 판정 설계

### 저장하는 내용

| 기록 | 주요 필드 | 사용처 |
|---|---|---|
| 잎 증거 | 표본 ID, 모양/가장자리, 정규화한 관찰 위치 또는 부위 ID, 특징 선택, 그림 버전 | 분류·새 표본 비교 |
| 분류판 | 기준 ID별 표본 배치, 비교한 식물 ID | 보고 |
| 계절 사진 | 개체 ID, 올해/다음 해, 계절, 땅속 상태, 표시한 부위, 그림 버전 | 증거 분석 |
| 실험 시도 | 표본 ID, 물속 여부, 누르기 관찰, 선택한 현상, 비교 특징 | 서식지 |
| 정원 점검 | 지형·배치 리비전, 연결한 증거 ID, 점검 결과 | 지도·최종·엔딩 |
| 발명 시험 | 설계 스냅샷, 시험 조건 ID, 모형 버전, 결과, 학생 관찰 | 비교·최종 |
| 발명 비교 | 이전/이후 시험 ID, 바꾼 부품, 결과 연결 | 완료 판정 |
| 설명 나누기 | 소개할 설계 ID, 혼자/함께 활동, 질문 유형, 수정/유지 선택, 자기 확인 여부 | 소통 지원, 교사 확인과 구분 |

매 프레임의 포인터 경로, 압력, 기기 센서, 개인정보는 저장하지 않는다. 사진은 상태와 그림 참조로 재구성하며 base64 화면 캡처를 localStorage에 누적하지 않는다. 기록은 조작 종료·증거 확정·시험 완료 시 저장한다.

### 판정 규칙

- 화면 효과 종료와 학습 완료를 분리한다. 애니메이션을 줄여도 동일한 결과와 판정에 도달한다.
- 예상은 오답 처리하지 않는다. 현상 선택과 설명은 다시 보고 수정할 수 있다.
- 가방 비교 쌍은 조건 ID·모형 버전이 같고, 설계 변수 하나만 달라야 한다.
- 기본 완료는 한 비교 쌍의 변경 부품과 결과 설명을 확인한다. 두 비교 쌍의 변경 변수가 겉면·덮개를 모두 포함하는 조건은 확장 기록에만 적용한다.
- 가방 완료는 최신 설계와 시험의 일치, 식물 특징 활용, 비교 설명을 확인한다. 모형의 두 기능 성공과 교육과정 성취를 별개로 기록한다. 시험 중 부품 변경은 막고, 화면 이탈 시 진행 중인 시험을 취소한다.
- 정원 점검은 현재 지형·배치 리비전과 일치해야 한다. 지형을 수정하면 관련 배치·근거·점검 상태를 다시 검증한다.
- 관리자 해금은 화면 접근만 허용한다. 새 증거·시험·완료를 자동으로 만들지 않는다.

### 기존 저장 이관

신규 저장은 `green-garden-mvp-v2`와 명시적인 스키마 버전을 사용한다. v2가 없을 때만 v1을 읽고 검사한 뒤 이관하며 기존 키는 삭제하지 않는다.

- 기존 완료·빛씨앗·꽃길·정원·가방은 보존한다.
- 기존 체크 기록을 학생이 직접 짚은 새 증거로 위조하지 않는다. `legacy` 기록으로 분리한다.
- 이전에 끝낸 미션과 엔딩은 ‘기존 탐구 완료’로 유지한다. 이미 받은 보상과 접근을 박탈하지 않는다.
- 새 활동으로 재탐구할 때는 새 증거 조건을 적용하되 과거 완료 기록과 분리한다. 새 비교를 마치면 해당 연구 기록을 갱신한다.
- v2 쓰기가 실패하면 기존 기록은 보존하고 현재 세션에서 탐구를 계속한다. 실패를 숨기거나 무한 이관을 반복하지 않는다.
- v1의 보상과 v2의 재탐구 성과를 합산해 빛씨앗을 중복 지급하지 않는다.

## 6. 구현 구조와 에셋

현재 JavaScript ES modules + DOM/CSS/SVG를 유지한다. 기존 화면을 한꺼번에 교체하지 않고 공통 화면 틀과 활동 단위로 옮긴다.

| 영역 | 제안 책임 |
|---|---|
| `src/model.js` | 기존 규칙 진입점, 새 순수 판정 함수 연결 |
| `src/learning/evidence.js` | 증거 생성·연결·유효성 |
| `src/learning/experiments.js` | 정원·가방의 조건과 결과, 비교 쌍 판정 |
| `src/state/migrate.js` | v1/v2 검사·이관·기존 완료 보존 |
| `src/ui/activity-shell.js` | 제목·무대·도구·증거 서랍 공통 배치 |
| `src/ui/pointer-tools.js` | 드래그·핀치·취소 처리와 대체 입력 연결 |
| `src/activities/` | 관찰·계절·실험·정원 활동별 표현과 입력 |
| `src/invention.js` | 가방 제작·같은 조건 비교·결과 표현 |
| `src/data/learning-content.js` | 부위 영역, 특징 보기, 단계 문구와 힌트 |

이 경로는 구현 계획이다. 중복 상태 저장소를 만들지 않고 기존 상태와 연결한다. 새 모듈 분리는 해당 활동을 수정할 때 수행한다.

기존 식물·가방·캐릭터 WebP를 재사용한다. 새로 필요한 것은 검수한 잎 부위 확대 그림, 계절 전환용 식물 부분 그림, 잎자루 변형·단면 표시, 가방 입구와 물방울 경로다. 학습 판정 영역과 현상 경로는 SVG/DOM으로 제어한다. 생성 이미지의 우연한 형태를 정답 판정 기준으로 사용하지 않는다.

### 로딩

- 신규 기능 때문에 시작 화면에서 전체 활동 이미지와 모듈을 불러오지 않는다.
- 초기 필수 항목은 앱 셸·설정·저장 검사·홈 대표 그림·기존 제목·필수 캐릭터로 한정하고, 단계별 모듈은 진입 시 가져온다.
- 첫 관찰은 표본 3종과 필요한 관찰 도식만 요청한다. 계절·기포·가방 에셋은 각 활동에서 불러온다.
- 기존 0.3의 실제 초기 요청 수·압축 전송량을 구현 시작 전에 측정한다. 현재 문서에는 측정하지 않은 수치를 적지 않는다. 목표는 첫 화면 전송량 증가 없이 첫 활동을 열고, 새 에셋을 해당 활동 요청으로 제한하는 것이다.
- 요청 수·전송량·첫 활동 준비 시간을 전후 비교한다. 필수 파일 실패 시 파일명과 재시도를 제공하고 선택 효과의 실패는 학습을 막지 않는다.

## 7. 구현 순서와 수용 기준

| 순서 | 범위 | 완료를 확인하는 장면 |
|---|---|---|
| 1 | 활동 셸·증거 서랍·저장 이관 기반 | 가로 태블릿에서 대상·도구·결과가 한 화면에 보이고 과거 진행을 유지 |
| 2 | 가방의 경로 표현·한 부품 비교 | 코팅만 바꿨을 때 겉면만 달라지고, 덮개를 바꾸면 수첩 결과가 달라짐 |
| 3 | 잎 관찰·기준 선택 분류 | 기본은 한 기준으로 완료, 선택 비교에서는 이전 판이 남음 |
| 4 | 계절 이동·사진 증거 | 겨울 땅속과 다음 봄의 같은 식물을 연결해서 설명 |
| 5 | 잎자루 조작·서식지 증거 | 물속 누르기 현상을 보고 원인과 서식지 연결 |
| 6 | 정원 점검·발견 모음·설명 나누기 | 내 결과로 친구와 이야기하고 개인 완료와 소통 확인을 구분 |

구현 순서와 학생의 탐구 순서는 다르다. 학생은 기존 1~10장 순서를 유지하되 확장 활동은 기본 완료를 막지 않는다. 후속 요청에 따른 실행 계획은 연결 문서에서 관리하며 이번 재검토 시점에는 실행 코드를 변경하지 않았다.

### 기능 검증

- 새 모형 규칙: 아무 입력 없이 완료되지 않음, 예상이 틀려도 진행 가능, 증거 누락·불일치 차단.
- 가방: 네 조합, 한 변수 비교, 두 변수 변경 비교 제외, 시험 중 이동·중복 실행, 최신 설계 일치.
- 정원: 한 획 Undo, 손가락 취소, 지형 수정 후 배치·점검 무효화, 정답 최초 배치도 완료 가능.
- 저장: 정상/손상 v1, 정상/손상 v2, 저장 실패, 재접속, 기존 보상 보존, 관리자 미리보기.
- 변경 단계마다 `npm run check`, `npm test`, `npm run build`와 관련 브라우저 확인을 수행한다. 본 설계 작성은 앱 변경이 아니므로 빌드 통과를 구현 완료 근거로 사용하지 않는다.

### 화면과 실제 기기 검증

- 1280×800·1024×768·1280×720에서 기본 글자일 때 핵심 대상·실행 도구·결과를 스크롤 없이 확인한다.
- 큰 글자·세로 화면·확대 보기에서는 콘텐츠와 모든 조작에 스크롤로 접근할 수 있다.
- iPad Safari와 Android Chrome에서 드래그·핀치·브라우저 스크롤의 충돌, 회전, 주소창 변화, 두 손가락 취소를 확인한다.
- 핵심 활동을 터치, 선택 후 누르기, 키보드로 각각 완료할 수 있다.
- 교실망 동시 접속은 별도 실제 기기 시험으로 확인하고 자동 시험과 구분해서 기록한다.

### 학생 사용성 확인

초기 소규모 관찰에서 교사가 조작법을 계속 알려 주지 않아도 첫 행동을 찾는지, 변화가 생긴 이유를 화면의 증거로 설명하는지, 예상과 달랐을 때 스스로 다시 조작하는지 확인한다. 단순 만족도 점수보다 아래 발화를 관찰한다.

- “이 부분을 크게 보니까 톱니가 보여요.”
- “겨울에도 뿌리가 남아 있고, 다음 봄에 여기서 다시 자라요.”
- “코팅은 겉면을 바꿨고, 덮개는 입구로 들어오는 비를 막았어요.”

첫 행동을 찾지 못하면 안내를 늘리기 전에 도구 배치를 고친다. 결과는 맞히지만 이유를 설명하지 못하면 비교 장면과 증거 연결을 보완한다. 모형을 실제 식물이나 제품의 모든 상황으로 일반화하면 해당 장면의 범위 표현을 수정한다.

- [현재 TRD](../TRD.md): 정적 앱 구조, 저장·입력·모형 경계.
