## 고친 곳

- `src/korean-linebreak.css` 새 파일(공통 파일 그대로 복사 + 아래 「프로젝트 보정」 절), `index.html`에서 다른 스타일보다 먼저 링크. `scripts/build.mjs`가 `index.html`의 스타일 링크를 순서대로 `src/bundle.css` 하나로 묶으므로 빌드 수정은 필요 없고(번들 맨 앞에 들어감), 서비스워커는 `bundle.css`를 미리 받아 두므로 `sw.js`도 그대로다.
- 공통 규칙만으로 고쳐진 곳: 본 탐구 2·3쪽 되짚기 선택지 버튼 4개(1920 「…봄에 다시 / 자랐어.」).
- 프로젝트 보정(`polish.css`의 `:is(p,li,…,.guide-bubble){text-wrap:pretty}`가 공통 규칙보다 우선이라 끝줄 외톨이가 남던 곳에 `text-wrap: balance`):
  - `.guide-bubble` — 현장 2·4장 리피 안내 말풍선(1920 「…/ 끌어 줘.」, 「…/ 흘러가는지 살펴봐.」)
  - `.direct-hint`, `.microcopy` — 본 탐구 4쪽 안내(「…물속 잎자루를 / 눌러 봐.」, 「…/ 물속에서 눌러 봐.」)
  - `.reason-cards > p` — 본 탐구 4쪽 까닭 질문(「…/ 도움을 줄까?」)
  - `.garden-confirm p` — 본 탐구 7쪽 정원 확인(「…/ 골라 줘.」)
  - `.prediction-step` — 본 탐구 9쪽 시험 결과 줄(「…/ 공책 젖음」)
  - `.sw-label` — 현장 3장 뜰까 가라앉을까 스위치(「가라앉을 것 / 같아」→「가라앉을 / 것 같아」)
  - `.heft-inside`, `.habitat-compare-card small` — 1024에서 「…/ 채웠어」, 「…/ 수 있어」
  - `.map-locked-message p` — 잠긴 장소 안내 창(「…다음 / 장소가 열려!」)
  - `.timeline` + `.timeline > .direct-hint { display: block }` — 본 탐구 2쪽 시간 손잡이 안내가 아래 입력 막대와 한 문단으로 묶여 balance가 듣지 않았다. 막대는 원래 다음 줄이라 글만 블록으로 뺐다(막대가 5~7px 내려감, 장면 넘침 없음 확인).
- 공통 파일 위쪽은 바꾸지 않았다. 루트 세션에 알릴 점: 프로젝트가 `:is(p, …)`처럼 0-1-0 우선순위로 `text-wrap: pretty`를 주면 공통 규칙이 지고, Chrome의 `pretty`는 2줄 문단의 짧은 끝줄을 고치지 않는다(이 프로젝트 실측). 인라인 글 뒤에 `inline-block` 입력이 같은 문단에 있으면 balance가 그 줄까지 포함해 계산한다.
