# 부레옥잠 잎자루 모형 확인과 재생성 자료

2026-10-23 요청: 현재 실험이 Meshy 결과물을 쓰는지, 납작해서 대체한 것인지 확인하고 필요하면 초기 이미지와 프롬프트 제공.

## 확인 결과

- 파일 누락이나 로딩 오류에 따른 임시 화면이 아니다. 현재 `src/spatial.js`의 `kind==='lab'` 분기는 Meshy GLB 대신 코드 도형으로 잎자루를 만든다. 잎자루 전체·단면 파일은 모두 보관되어 있으나 이 실험에서 로딩하지 않는다.
- Git 변경 `6cf8005`에서 `model(cut?'petiole_cut':'petiole_whole',group,1.25)`가 제거되고 코드 모형으로 바뀌었다. 해당 주석은 기존 단면 GLB의 깊이가 0.25라 납작하게 보였다고 기록한다.
- GLB의 POSITION accessor 경계와 노드 변환을 적용해 원본·최적화본 치수를 대조했다. 축에 정렬한 경계상자 기준이며, 조직 내부의 실제 두께 측정이나 모델 수리 가능성 판정은 아니다.

| 파일 | 폭 X | 높이 Y | 깊이 Z | 깊이/높이 |
|---|---:|---:|---:|---:|
| 자르기 전 원본 | 0.9636 | 1.9039 | 1.6462 | 0.865 |
| `petiole_whole.glb` | 1.0115 | 2.0000 | 1.7286 | 0.864 |
| 단면 원본 | 1.7741 | 1.9030 | 0.2391 | 0.126 |
| `petiole_cut.glb` | 1.8654 | 2.0000 | 0.2522 | 0.126 |

단면은 최적화 이전부터 납작했다. 최적화 과정에서 두께를 잃은 것이 아니다. 자르기 전 모형의 재생성은 우선 필요하지 않다. 단면은 단순 Z축 확대만으로 내부 빈 공간의 형상까지 복구된다고 보장할 수 없어 재생성을 권한다.

기존 입력은 정면에 가까운 단면으로 두께 단서가 적다. 이것이 생성 형상에 영향을 주었을 가능성은 있지만, 원인으로 확정한 것은 아니다.

## 새 GLB를 받은 뒤 확인할 것

1. 정면에서 90도 회전해도 부푼 잎자루의 두께가 남아 있는지 확인한다. 옆면 폭이 본체 최대 폭의 약 65~80%인 것은 이번 제작 목표이며, 생물학적 실측 기준은 아니다.
2. 공기 공간이 평면에 칠한 무늬가 아니라 깊이가 있는 내부 구조인지 확인한다.
3. 기존 전체 모형과 길이·방향·외형을 맞춰 자르기 전후가 같은 표본으로 보이도록 배치한다.
4. 기존 파일을 보관한 뒤 새 단면을 최적화하고 실험 코드에 GLB 로딩을 다시 연결한다. 파일 이름만 바꾸면 현재 코드 모형이 자동 교체되지는 않는다.
