# 초록정원 태블릿 탐구 개편 실행 계획

기준일: 2026-10-16. 기준 설계: [태블릿 탐구 경험 2차안](TABLET-EXPERIENCE-DESIGN-20261016.md). 선행 검토: [학생 UX와 성취기준](reviews/UX-CURRICULUM-REVIEW-20261016.md).

이번 개편은 **학생이 할 일을 바로 찾고, 적은 조작으로 관찰·분류·설계·설명에 도달하는 것**을 목표로 한다. 상호작용 개수 자체를 늘리는 것을 완료 기준으로 삼지 않는다.

## 현재 상태

- 전체 화면과 기존 판정·저장 구조 확인: 완료.
- 2022 개정 과학 성취기준과 학생 UX 재검토: 완료.
- 기본/확장 활동, 쉬운 제목·문구, 소통 활동을 반영한 상세 설계: 완료.
- 아래 실행 단계: 미착수. 실제 앱 0.3은 아직 변경하지 않음.

## 작업 순서

| 단계 | 작업 | 주요 파일·범위 | 통과 기준 |
|---|---|---|---|
| 1 | 학생 화면 셸과 문구 정리 | app.js, model.js의 표시 문구, style.css 계열, 활동 셸 | 현재 판정·저장은 유지. 1024×768·1280×800에서 대상·핵심 도구·결과를 함께 표시. 제목·지시·버튼 역할 분리 |
| 2 | 증거 상태·기존 기록 이관 | model.js, state/migrate.js, evidence.js | 과거 완료·보상·정원 보존, 미수행 새 증거를 만들지 않음. 기본/확장 완료 분리 |
| 3 | 잎 관찰과 분류 | app.js의 specimen/classification 분리, 활동 데이터 | 큰 부위 선택→특징 선택으로 기록. 기준 1개만으로 기본 완료. 다른 기준은 선택 |
| 4 | 가방 제작·비교 시험 | invention.js, art.js, 모형 판정 | 같은 조건의 한 부품 비교, 시험 중 물의 경로, 관찰과 해석 분리, 기본 1쌍/확장 2쌍 |
| 5 | 계절·사는 곳·잎자루 | seasons/evidence/experiment/habitats, 제공 관찰 카드 | 겨울·봄 2장 기본, 기포 직접 조작과 누르기 대안, 환경 관찰 후 까닭 연결 |
| 6 | 정원·발견 모음·소통·엔딩 | gardenBuild/gardenPlace/report/final/ending/rewards | 기본 정원 제공, 수정한 부분 재점검, 반복 제출 제거, 내 설계 설명과 친구 의견, 개인 완료/소통 확인 구분 |
| 7 | 전체 흐름·성능·교실 준비 검증 | 전체 경로·배포 산출물·검수 문서 | 보상 중복 없음, 새로고침·재탐구 정상, 실패 파일 안내, 첫 접속 측정, 실제 기기와 학생 검증 결과 구분 |

각 단계는 작은 변경으로 나누고 관련 검증 후 다음 단계로 이어 간다. 활동별 완료 판정 변경은 화면·안내·저장·최종 판정·테스트를 같은 단계에서 갱신한다. 새 화면만 붙여 기존 조건과 충돌시키지 않는다.

## 1단계 상세 화면 명세

공통 틀은 메뉴 / 짧은 제목과 지금 할 일 / 큰 대상과 도구 / 결과 한 줄 / 탐색으로 구성한다. 첫 구현은 ‘잎을 살펴봐요’와 ‘가방에 비를 뿌려요’를 기준 화면으로 검증한 뒤 다른 활동에 적용한다.

| 상태 | 학생에게 보여 주는 것 | 주요 행동 | 표시하지 않을 것 |
|---|---|---|---|
| 처음 | 대상과 현재 지시 1개 | 부위 선택 또는 비 뿌리기 | 긴 연구 기록, 전체 사용법, 여러 단계 실행 버튼 |
| 선택함 | 선택한 대상의 테두리·이름 | 특징 고르기 또는 부품 고르기 | 다른 대상의 완료 조건 |
| 관찰 중 | 변화하는 부분과 관찰 위치 | 멈춤/다시 보기 | 다음 활동 강조 |
| 기록됨 | 관찰 그림·선택한 특징·저장 표시 | 다음 대상 또는 하나 바꾸기 | 별도 ‘저장 확인’ 팝업 |
| 더 필요함 | 남은 대상 이름과 행동 | 해당 대상으로 바로 이동 | ‘조건 미충족’ 같은 추상 설명 |
| 기본 완료 | 이번 발견 한 줄 | 다음 탐구 | 확장 활동을 하지 않았다는 경고 |

1단계에서는 기존 기능을 유지하는 표시·배치 변경만 수행한다. 증거 기반 완료 판정과 소통 상태는 이후 단계에서 함께 교체한다. 단계 1 배포를 새 학습 경험 전체의 완료로 표시하지 않는다.

## 중복 설명 정리 규칙

1. 제목은 활동 이름만 표현한다.
2. 지시는 지금 할 행동 하나를 말한다.
3. 도구 이름은 실제 누르면 일어나는 행동을 말한다.
4. 결과는 방금 관찰한 변화를 말한다.
5. 기록은 학생이 선택한 증거를 보존한다.

같은 문장을 이 다섯 곳에 반복하지 않는다. 설명이 더 필요하면 대상 옆 도움말로 제공한다. 설명을 숨겼다는 이유로 핵심 완료 조건까지 숨기지 않는다.

## 판정과 회귀 검증

- 기본 분류 완료가 두 번째 기준 작성에 의존하지 않는지 확인한다.
- 선택하지 않은 계절·알로에 상세 비교가 다음 장을 막지 않는지 확인한다.
- 제공 관찰 카드와 학생이 실제 남긴 기록을 구분한다.
- 가방의 현재 설계와 시험이 어긋났을 때 재시험 이유를 표시한다.
- 한 부품 비교에 두 부품을 바꾼 기록을 잘못 포함하지 않는다.
- 성공 조합을 고른 사실만으로 식물 특징 설명과 협력적 소통을 완료 처리하지 않는다.
- 혼자 탐구해도 진행 가능하며 소통 상태는 미확인으로 남는다.
- 과거 저장 복원 후 새 미션 우회·보상 중복·정원 손실이 없다.
- 모션 감소와 키보드에서도 같은 학습 결과에 도달한다.

필수 명령은 `npm run check`, `npm test`, `npm run build`다. 현재 check 스크립트는 src 직하위만 확인하므로 하위 모듈을 도입하는 2단계에서 재귀 검사를 함께 수정한다. 테스트와 빌드가 통과한 뒤 실제 브라우저에서 해당 활동을 끝까지 확인한다.

## 학생·교사 확인

실제 초등학생에게 처음 할 일, 막힌 이유, 비교 결과를 설명하게 하여 이해 여부를 확인한다. ‘재미있다’만으로 통과하지 않는다. 친구와의 설명·질문·수정 대화는 교사가 관찰하고, 앱은 이를 자동 채점했다고 표시하지 않는다. 특정 교과서의 학기·차시 순서는 해당 판본으로 최종 대조한다.

앱 구현 완료, 실제 태블릿 확인, 학생 사용성 확인, 교실 동시 접속 확인, 배포 완료는 각각 별도로 기록한다.
